# Eval run, 2026-10-20 (JVM plugin set)

Evals for the plugin set in `docs/plans/jvm-meta.md`: `java`, `java-testing`, `maven`, `gradle`, `scala`, `sbt`, `play-framework`, `spring-boot`, `spring-boot-testing`, plus the paired routing suite `evals/jvm`. Claude Code 2.1.306, `--no-publish`; results are in the gitignored `evals/results/` folders.

Cost: about $6.60 for the first per-plugin pass, $3.12 and $3.39 for the two full paired runs, and about $3.30 for the reruns after fixes. About $16.40 in total, inside the plan's $15–20 estimate.

## Per-plugin (36 cases, one run each, with the no-plugin baseline)

Each plugin has 2 trigger cases, 1 hard negative (`min: 0 max: 0 arm: both`) and 1 outcome case. All 36 pass with the plugin. Every trigger case scored 0.00 without it, and every negative stayed quiet in both arms.

- **Prompts that ask a bare question don't test triggering.** `spring-boot`'s two trigger prompts were questions the model answered from memory; with code and a task attached, both fire.
- **Two graders were wrong and were fixed, not the skill.** `sbt2-commands` false-failed on an answer that quoted the old command. A review then found it also passed wrong fixes, so it now reads `.github/workflows/ci.yml` and requires `testFull`. `gradle-config-cache` had a `not_contains` that failed correct answers quoting the broken snippet; it was dropped in favour of the llm grader.
- **One real skill fix from a judge.** `gradle-config-cache` failed once because the answer used `providers.provider { project.version }`, which still reads `project` at execution time. That pattern is now in the skill's config-cache table.
- **Outcome cases that don't separate the arms.** The baseline also scores 1.00 on `play-migrate-3`, `boot-config-props`, `junit-clock`, `scala-follow-style` and `slice-test`, so those cases show only that the skill does no harm. `java-upgrade-21` (+0.50), `maven-bom` (+0.20) and `sbt2-commands` (+0.25) do separate.

## Paired routing (evals/jvm, 18 cases, 3 runs, no baseline)

All nine plugins, the pinned `3rd-party/gradle-skills` clone and the `programming-core` skill plugins load together. Run from the repo root (the clone must exist first; see `evals/jvm/README.md`):

```
claude plugin eval . --eval-dir evals/jvm/evals --trust-plugin --ablation none -j 4 --no-publish
```

- **First run: 10 of 18.** Every failure was "no skill fired": the model answered directly. No run misrouted to a sibling. The boundaries between siblings held: `gradle` vs `gradle-skills`, `maven` vs `java`, `play-framework` vs `scala`/`java`/`spring-boot`/`sbt`, and `spring-boot-testing` vs `java-testing`.
- **Fixes:** the `java`, `java-testing`, `scala`, `spring-boot-testing` and `unit-testing` descriptions now name the symptoms those prompts give: a `MatchException` or a non-exhaustive sealed switch, `javax.*` imports on Jakarta EE 9+, `UnnecessaryStubbingException`, `@ParameterizedTest`, "cannot find an ordering", a MUnit suite, a `@WebMvcTest` with a missing bean, and general test-strategy questions.
- **Second run: 17 of 18** (overall score 0.98).
- **The one failure is `missing-given`,** which fired `scala` in 1 of 3 runs (2 of 3 in an earlier single-case rerun). The prompt is a one-line "List[Money] won't sort" question, and the description already names the error, so the model answering from memory is a borderline call, not misrouting. It is left as a known flaky case rather than tuning the prompt until it passes.

## Metals smoke test (run 2026-10-21)

Metals 1.6.9, sbt 1.11.7, Scala 3.3.6, JDK 27, Claude Code 2.1.306, a one-file sbt project with a type error and a syntax error.

- **First result, failure:** Metals asked "New sbt workspace detected, would you like to import the build?" through `window/showMessageRequest`. Claude Code's LSP client does not implement it, so Metals logged `Unexpected error initializing server: ... Unhandled method window/showMessageRequest` and shut down. No diagnostics reached the session.
- **Fix (scala 0.1.2):** `"settings": {"metals": {"autoImportBuilds": "all"}}` in `.lsp.json`. Claude Code sends it via `workspace/didChangeConfiguration`, and Metals runs `sbt bloopInstall` without asking.
- **Result:** in a fresh project the session received the Bloop diagnostics for `Shapes.scala` (`Found: ("text" : String) Required: Int`, `Missing return type`, `expression expected but eof found`), delivered with the tool result after a 60 s wait.
- **Caveats:** two later prompts (HTTP server for the Doctor, a "mis-configuration" warning) still arrive and get an error reply; they are not fatal. Before the first compile Metals sends parser-only `scalameta` diagnostics. A foreign sbt holding `~/.ivy2/.sbt.ivy.lock` stalled one import, and a `mise` sbt shim with no active version failed it; both are environment problems.
- **Eval after the fix:** 4 of 4 cases pass, $0.41.
