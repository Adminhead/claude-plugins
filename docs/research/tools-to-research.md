## Graphify-Labs/graphify

- **What:** `/graphify .` parses a repo with tree-sitter (about 40 languages, no LLM) into a knowledge graph (`graph.json`, `graph.html`, `GRAPH_REPORT.md`) with Leiden communities, "god nodes", and `EXTRACTED`/`INFERRED` edge tags. `graphify query|path|explain` answer questions against the graph. Docs, PDFs, images and video go through an optional semantic pass that uses the assistant's model or a configured API key.
- **Consumed as:** Python CLI (`uv tool install graphifyy`, note the double y) plus `graphify install`, which writes a `/graphify` skill into `~/.claude/skills/` (or `.claude/skills/` with `--project`) and, on Claude Code, a PreToolUse hook that fires before Grep/Glob/Read and nudges toward the graph. Optional `[mcp]` extra gives a stdio MCP server; `graphify hook install` adds git hooks that rebuild on commit.
- **Language / license / stars / pushed:** Python; Apache-2.0 (plus MIT file); 127,682 stars; pushed 2026-10-16 (v0.9.92 released that day). Very active, backed by Graphify Labs, with a Graphify Cloud upsell in the README.
- **Fit:** Candidate for the code-intel slot the archived `code-search` plugin filled with CodeGraph (`archive/docs/plugins/code-search.md`; a `.codegraph/` index still sits in this repo). A wrapper plugin would ship its own skill that calls the `graphify` CLI, and install the tool from a SessionStart hook the way archived coremods installed DuckDB, rather than letting `graphify install` write into `~/.claude`.
- **Risks:** Heavy dependency set (27 tree-sitter wheels, networkx, numpy, rapidfuzz; extras pull matplotlib, graspologic, whisper). The PreToolUse hook on every Grep/Read is noisy and would fight any search-guideline mod. The semantic pass over docs needs an API key or burns session tokens. Every query is logged to `~/.cache/graphify-queries.log`. Overlaps with codebase-memory-mcp and CodeGraph; only one of the three should be in a plugin.
- **Verdict: investigate more.** The graph quality and the docs/ADR ingestion are the differentiators; the install footprint and hook behavior are the cost. Next step: `uv tool install graphifyy`, run `graphify . --no-viz --code-only` on this repo and one mid-size project, compare `graphify query` against `codegraph_explore` and codebase-memory-mcp's `search_graph`/`trace_path` on the same five questions, and inspect what `graphify claude install --project` actually writes before deciding.

## DeusData/codebase-memory-mcp

- **What:** Local MCP server that indexes a repo into a SQLite-backed knowledge graph (162 tree-sitter grammars compiled in; Linux kernel in about 3 minutes) and exposes 17 tools: `index_repository`, `search_graph`, `trace_path`, `detect_changes` (git diff to blast radius), `query_graph` (Cypher-like), `get_architecture`, `get_code_snippet`, `get_file_outline`, `search_code`, `manage_adr`, `compare_graphs`, and more. Also indexes Dockerfiles, compose, Kubernetes and Kustomize as graph nodes. "CBM Lens" is a browser UI (3D graph, Monaco reader, local WebGPU chat model) on `main`, not yet in a release.
- **Consumed as:** Single static binary (macOS/Linux/Windows, also AUR and a Nix flake) via `curl ... install.sh | bash`. `install` auto-configures 45 clients; for Claude Code it writes an MCP entry in `~/.claude.json`, a `codebase-memory` skill, three read-only graph agents, and `SessionStart`/`SubagentStart`/non-blocking `PreToolUse` hooks. `--skip-config` installs the binary only, and manual config is a two-line `mcpServers` entry. A per-account coordination daemon is shared across clients.
- **Language / license / stars / pushed:** C (80 MB of source) with TypeScript UI; MIT; 46,765 stars; pushed 2026-10-17 (v0.12.1 released 2026-10-16). Releases land every few days; an arXiv preprint (2603.27277) backs the token-saving claims.
- **Fit:** The cleanest plug-in of the two code-intel tools: a plugin `.mcp.json` pointing at the binary, a SessionStart hook that fetches the release archive with `--skip-config`, and a skill. `3rd-party/awesome-copilot/skills/codebase-memory-mcp/SKILL.md` (MIT) already exists as a skill to adapt. The challenger to CodeGraph for a revived `code-search` plugin: more tools (17 against CodeGraph's one) and infra-as-graph nodes, at the cost of a larger tool menu.
- **Risks:** Piped installer (archived coremods `tool-mgr` asks before those; pin a release tarball instead). Shared daemon requires every CBM process to be the exact same build, so a plugin-managed binary and a user-installed one can conflict. Microsoft Defender false positives are documented. Lens beta and the install flow are moving fast. Overlaps with graphify and CodeGraph.
- **Verdict: helpful.** Next step: download the v0.12.1 Linux tarball into a scratch dir, run `./install.sh --skip-config --dir=<scratch>`, add it to a throwaway plugin's `.mcp.json`, index this repo, and time `get_architecture` and `trace_path` against the CodeGraph answers; if it wins, design the SessionStart installer and data-dir layout like archived coremods did for DuckDB.

## colbymchenry/codegraph

Added 2026-10-17.

- **What:** A pre-built code knowledge graph (symbols, call edges, dependencies, dynamic-dispatch hops such as callbacks and interface-to-impl) stored in a per-project `.codegraph/codegraph.db` SQLite file. A file watcher keeps it in sync on every change, so there is nothing to re-run. About 35 languages, plus framework-aware routes and iOS / React Native bridging.
- **Consumed as:** A CLI with a bundled runtime (`curl ... install.sh | sh`, or `npm i -g @colbymchenry/codegraph`). `codegraph install` wires the MCP server (`codegraph serve --mcp`) into Claude Code and eight other agents; `codegraph init` builds a project's index. The MCP server lists a **single tool**, `codegraph_explore`, which returns verbatim source grouped by file, the call paths between symbols and a blast-radius summary. Seven narrower tools (`node`, `search`, `callers`, `callees`, `impact`, `files`, `status`) are hidden unless `CODEGRAPH_MCP_TOOLS` lists them, and all have CLI equivalents. `projectPath` lets one server answer for any indexed repo. Also usable as a library (`CodeGraph.init`, `buildContext`, `getImpactRadius`).
- **Language / license / stars / pushed:** C core with a Rust kernel and TypeScript wrapper; MIT; 74,333 stars; pushed 2026-10-17 (v1.6.2 released 2026-10-03). npm packages carry provenance and release bundles carry signed SLSA build attestations.
- **Local state:** v1.6.2 is installed here through mise, and this repo already has a `.codegraph/` index with a running watcher daemon. No `codegraph` MCP server is configured in Claude Code right now (`claude mcp list` shows none), because the archived `code-search` plugin that shipped it is no longer installed.
- **Fit:** It is what the archived `code-search` plugin used (`archive/docs/plugins/code-search.md`): a stdio `.mcp.json` entry with `alwaysLoad: true`, a `code-search:codegraph` skill, a guideline block telling Claude to call `codegraph_explore` before Grep or Read, and an async SessionStart hook that runs `codegraph init` in any git repo without an index. Reviving that plugin is the cheapest path to code intelligence, since every piece was already built and documented.
- **Risks:** Its own README says it leaves about 80% more retrieval context resident by the end of a long session (67k against 18k tokens on VS Code), because each `codegraph_explore` answer is one dense payload that stays in the window. Anonymous telemetry is on unless declined at install (`codegraph telemetry off` or `DO_NOT_TRACK=1`). The archived notes record that a user-level `codegraph` server silently shadows the plugin's copy, and that `codegraph` must be on PATH with no npx fallback. The README promotes a hosted platform waitlist. The benchmark numbers (88% fewer tool calls, 44% cheaper) are the author's own, though the methodology is published and blocks the CLI in both arms.
- **Verdict: helpful.** It is the incumbent, already installed and proven in this repo's own plugin, so it is the baseline the other two code-intel tools have to beat. Next step: restore `archive/plugins/code-search` into `plugins/`, run `codegraph telemetry off`, and use the same five-question comparison planned for graphify and codebase-memory-mcp, recording resident context as well as tool calls. Keep at most one code-graph MCP server in the shipped plugin.

## tt-a1i/archify

- **What:** An agent skill that turns a description, plan or codebase into an interactive, self-contained HTML diagram (architecture, workflow, sequence, data flow, lifecycle, ERD, class, tree, timeline, waterfall). The agent writes typed JSON against a schema; `node bin/archify.mjs finalize <type> <candidate.json> <out.html> --quality showcase --json` validates, renders, runs strict checks and a real-browser check, and emits a receipt. Output supports path tracing, themes, PNG/share-card export, and source links back to the repo (`--repo-root`).
- **Consumed as:** Skill directory `archify/` (SKILL.md about 16 KB, `bin/`, `schemas/`, `renderers/`, `references/`, `recipes/`, `examples/`, own `package.json`) installed with `npx skills add tt-a1i/archify -g` (the skills.sh CLI). No `.claude-plugin/` manifest and no Claude Code marketplace; integrations exist for DeepSeek Harness and Hermes. Needs Node.
- **Language / license / stars / pushed:** JavaScript; MIT (skill dir carries its own LICENSE and THIRD_PARTY_NOTICES); 84,794 stars; pushed 2026-10-17 (v3.1.0 on 2026-10-13). Chinese-origin project with a paid-sponsor table, #1 on GitHub Trending in September 2026, cited in both awesome lists.
- **Fit:** Vendor `archify/` as `plugins/<diagrams>/skills/archify/` (the skill references its own files by relative path, so it copies cleanly). It covers the "code to explorable diagram" case that `diagram-design` does not, and would pair with a code-intel plugin's graph output. Nothing in `3rd-party/` does this.
- **Risks:** The skill phones home for an update check (a GET of a manifest, about daily) unless disabled. `finalize` runs a browser-check gate, so verify what browser it needs (Playwright or system Chrome) and how it behaves headless. A vendored copy drifts from a repo that releases often, so pin the tag and record it. SKILL.md is long and reference-heavy; check how much it costs to load.
- **Verdict: helpful.** Next step: copy `archify/` at tag v3.1.0 into a scratch plugin, run `npm ci` inside it, run `finalize` on one of its examples offline (network blocked) to see the update check and browser gate behavior, then decide whether to vendor or to point a `github`-sourced marketplace entry at a fork that adds a `plugin.json`.

## cathrynlavery/diagram-design

- **What:** "Editorial" diagram skill: 45 types (architecture, flowchart, sequence, state, ERD, timeline, swimlane, quadrant, radar, Gantt, Sankey, Wardley, treemap, heatmap, kanban, journey, UML class, and so on) rendered as self-contained HTML with inline SVG and a tokenized style guide. An onboarding flow pulls a site's palette and fonts into a saved profile; commands import Mermaid, draw.io and Excalidraw and export SVG/PNG.
- **Consumed as:** Already a Claude Code plugin with its own marketplace: `/plugin marketplace add cathrynlavery/diagram-design` then `/plugin install diagram-design@diagram-design` (plugin v2.6.110, `.claude-plugin/plugin.json` and `marketplace.json`). Also `npx skills add`, Codex, Copilot, Factory Droid and Pi plugins. One skill (`skills/diagram-design/`, SKILL.md about 31 KB, `references/`, `assets/`, `scripts/`), six commands (`doctor`, `export-diagram`, `import-drawio`, `import-excalidraw`, `import-mermaid`, `profile`). Scripts are Python.
- **Language / license / stars / pushed:** HTML/Python; MIT; 56,905 stars; pushed 2026-10-16; frequent releases (version history tracked in `scripts/plugin_version_history.py`). Maintained by Cathryn Lavery / LittleMight; cited in both awesome lists.
- **Fit:** No wrapping needed. Two options from the README's "Plugins hosted elsewhere" section: a `github`-sourced entry in `.claude-plugin/marketplace.json` (`"source": {"source": "github", "repo": "cathrynlavery/diagram-design"}`), or treat it as a cross-install marketplace the way the archived `scripts/install.sh` added `conorbronsdon/avoid-ai-writing`. Complements archify (static editorial diagrams and charts versus explorable code maps) and the built-in `artifact-diagramming` skill.
- **Risks:** 31 KB SKILL.md plus references is a large context load per use. The first-use "style guide gate" pauses to ask about branding, which may annoy in a code-only repo (a `.diagram-design` profile marker bypasses it). Python scripts need a Python 3 on PATH. Third-party marketplaces do not auto-update unless enabled.
- **Verdict: helpful.** Next step: add the marketplace locally, run `/diagram-design` for a sequence diagram of a plugin install, and decide between a `github`-sourced marketplace entry (tracks upstream, no code in this repo) and an install-script cross-install; record the choice alongside the archify decision so the two diagram tools are documented together.

## hesreallyhim/awesome-claude-code

- **What:** The largest curated list of Claude Code resources: guides, Anthropic links, skills, agent orchestration, memory, observability, status lines, configuration, testing, linting, and "Lists & Collections". The README is generated from `THE_RESOURCES_TABLE_NEW.csv` by `generate_readme.py`; the list already cites archify, diagram-design, claude-hud and claude-plugins-official, and links `karanb192/awesome-claude-code-mods`, a community list of mods built on the mods API.
- **Consumed as:** A list of links. The repo is a Python generator plus CSV data, not something to install.
- **Language / license / stars / pushed:** Python; **CC BY-NC-ND 4.0** (GitHub reports "Other"); 55,892 stars; pushed 2026-10-17. Maintained continuously since 2025-04.
- **Fit:** A reading feed for finding mods, status lines and skills to evaluate, and a cross-check that a tool is known before vendoring it. The "Status Lines" section (CCometixLine, ccstatusline, claude-powerline, claude-hud, ...) and the mods list are the relevant inputs for `coremods`.
- **Risks:** NoDerivatives means no copying or reformatting the list into this repo (the README explicitly asks to be contacted for derived uses). Entries are community-submitted, so a listing is not a quality signal on its own. 236 unique GitHub repos linked, so triage cost is real.
- **Verdict: helpful** (as a source, never as content). Next step: read the Status Lines, Observability & Monitoring, Configuration and Lists & Collections sections once, open `karanb192/awesome-claude-code-mods` for mods-API examples, and add anything worth evaluating to `docs/Tools to research.md` by URL only.

## anthropics/claude-plugins-official

- **What:** Anthropic's official plugin directory: a marketplace manifest with 315 entries, split into `/plugins` (Anthropic-built: `code-review`, `commit-commands`, `claude-md-management`, `claude-security`, `frontend-design`, `feature-dev`, `agent-sdk-dev`, `explanatory-output-style`, LSP plugins such as `clangd-lsp`, `csharp-lsp`) and `/external_plugins` plus `github`/`git-subdir` sources for partner plugins (`context7`, `exa`, `firecrawl`, `atlassian`, `datadog`, `cloudflare`, `azure`, `aws-*`, `duckdb-skills`, `clickhouse`, `figma`, `chrome-devtools-mcp`, ...). The README documents immutable plugin names, a `renames` map, and `strict: false` skill-bundle entries for repos without `plugin.json`.
- **Consumed as:** A marketplace. `claude plugin marketplace list` on this machine already shows it registered as `claude-plugins-official` (next to the built-in `anthropic-plugin-directory`), so `claude plugin install <name>@claude-plugins-official` works today.
- **Language / license / stars / pushed:** Python tooling; Apache-2.0 for the directory, each plugin under its own license; 41,520 stars; pushed 2026-10-17.
- **Fit:** Two uses. First, cross-marketplace dependencies: `.claude-plugin/marketplace.json` already has `allowCrossMarketplaceDependenciesOn: ["claude-code-lsps"]`; adding `claude-plugins-official` lets an adminhead plugin depend on `context7` or `exa` instead of re-declaring their MCP servers as the archived `code-search` and `research` plugins did. Second, a recommended-cross-installs table in `README.md` (and in a revived `scripts/install.sh`) for `code-review`, `commit-commands`, `claude-md-management` and the LSP plugins rather than wrapping them. Its `skill-bundle` entry shape is also the model for listing archify-style repos without a `plugin.json`.
- **Risks:** Low. Anthropic warns it does not vet MCP servers in external plugins. Some entries duplicate what adminhead would build (`code-review`, `commit-commands`), so decide per plugin whether to defer or differentiate.
- **Verdict: helpful.** Next step: add `"claude-plugins-official"` to `allowCrossMarketplaceDependenciesOn`, list the entries that replace archived adminhead components (`context7`, `exa`, `firecrawl`, the LSPs), and write the cross-install table before reviving those plugins.

## jarrodwatts/claude-hud

- **What:** A status line for Claude Code: model, provider, project path, git or jj status, a context bar with warning/critical thresholds, subscriber rate-limit windows with reset countdowns and pace coloring, cost (session, daily, weekly ledger), prompt-cache expiry and hit rate, output speed, effort level, Claude Code version, and optional lines for active tools, skills, MCP servers, running agents and todo progress, parsed from the session transcript. Over 90 config options, English and Chinese labels.
- **Consumed as:** A Claude Code plugin from its own marketplace (`/plugin marketplace add jarrodwatts/claude-hud`, `/plugin install claude-hud`, then `/claude-hud:setup` points `statusLine` at `dist/index.js`). It is a **classic statusline command**, not a mod: the repo has `commands/`, `dist/`, `src/` and no `hooks/`, and nothing imports the `claude-code` mods module. TypeScript compiled to plain Node, zero runtime dependencies.
- **Language / license / stars / pushed:** TypeScript/JavaScript; MIT; 28,610 stars; pushed 2026-10-17 (v0.11.3 released that day). Has CHANGELOG, SECURITY, RELEASING, snapshot tests.
- **Fit:** The archived `coremods` drew a git status line, a usage band and an agent status line with the mods API (`$.ui`). claude-hud is the reference for the *data*: `src/stdin.ts` for the statusline stdin fields (`context_window`, `rate_limits`, `cost`, `transcript_path`), `src/transcript.ts` for deriving tool/agent/todo activity, `src/usage-pace.ts` and `src/daily-cost.ts` for the pace and ledger logic, `src/git.ts`/`src/jj.ts` for VCS status, and `src/render/` for layout and thresholds. It is not a reference for the mods API itself; for that use `karanb192/awesome-claude-code-mods` and the `claude-code.d.ts` types named in `CLAUDE.md`.
- **Risks:** It owns the single `statusLine` slot and would collide with any adminhead status-line mod; installing both means duplicated bars. Transcript parsing is coupled to Claude Code's JSONL format and breaks on upgrades (hence the frequent releases). Zero runtime deps and MIT make selective code reuse easy, with attribution.
- **Verdict: helpful** (as a mod reference, not as an install). Next step: when reviving the coremods usage band and agent line, read the five `src/` files above and port the field names, thresholds and pace heuristic into side files that take no `$`, per `CLAUDE.md`; cite claude-hud in the Acknowledgements table if any logic is adapted.
