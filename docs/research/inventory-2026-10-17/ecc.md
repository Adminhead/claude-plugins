# ECC inventory (3rd-party/ECC)

Source: https://github.com/affaan-m/ECC, MIT (c) 2026 Affaan Mustafa. Canonical surface: 311 skills (`skills/`), 71 agents (`agents/`), 97 commands (`commands/`), 1 production `hooks/hooks.json` with 58 Node scripts (`scripts/hooks/`). Locale and harness mirrors (`docs/<locale>/`, `pi/`, `.agents/`, `.kiro/`, `.cursor/`, `.codex/`, `.opencode/`) were ignored.

## Summary

- **Cross-dep: 0.** ECC is a single mega-plugin (`ecc@ecc`), and its hook graph (three-layer bootstrap, Stop/PreToolUse gates) would load into every session. It is the textbook case the brief rules out.
- **Port: 3.** (1) `check-bypass-guard`: one hooks.json built from `config-protection.js` plus a rewritten `block-no-verify.js`. It stops the agent from weakening linter configs or skipping git hooks instead of fixing the code. (2) `prisma`: the trap list from `prisma-patterns`, trimmed. (3) `open-source-release-audit`: an agent built on `opensource-sanitizer`, with the `opensource-pipeline` skill folded into it.
- **Merge: 33 rows** (about 70 source skills and agents). Most of ECC's on-stack content was already mined in the 2026-10-02 review and condensed into `archive/plugins/*`: db, deploy, observability, api, mcp, git, github, authoring, coding-*, testing, review, homelab, experiment-loop. Each of those archived skills is 35 to 130 lines, while the ECC source is 400 to 750. **The archived version wins in every merge row.** The one new merge is `mcp-dependency-review`, which is good and should go into the agent-config-audit successor.
- **Skip: everything else**, about 240 skills, 60 agents and all 97 commands. The reasons: off-stack domains (business, mobile, JVM, PHP, video, crypto, healthcare); ECC-internal harness tooling; overlap with built-ins (/code-review, /security-review, /simplify, Plan, Workflow, auto memory) or codebase-memory; or generic textbook "patterns" that Claude already knows.
- **Quality notes.** Many ECC agents start with a pasted "Prompt Defense Baseline", which includes "Do not output executable code ... unless required". That is wrong for a coding agent, and every port must strip it. Seven agents are thinner rewrites of Anthropic's official pr-review-toolkit and feature-dev agents. The language reviewers grade things like "return err without wrapping" as CRITICAL. Their descriptions say "MUST BE USED for Go projects", which would over-trigger delegation.
- **Gaps ECC does not fill:** Terraform/OpenTofu, Ansible, Helm, and GitHub Actions authoring. ECC also has no TypeScript-language skill; its typescript-reviewer says so itself.

## Open questions

1. Should `check-bypass-guard` go into baseline (every session) or programming-meta? It costs no tokens, but it prompts whenever an existing lint config is edited.
2. Is `open-source-release-audit` worth a plugin? Do you publish private repos often enough?
3. The official pr-review-toolkit and feature-dev agents (silent-failure-hunter, type-design-analyzer, and so on) are the originals that ECC copied. Add `claude-plugins-official` to `allowCrossMarketplaceDependenciesOn`, or leave them out?
4. Many merge rows point at `archive/plugins/*` skills, which were already condensed from ECC and other repos. Is reviving those archived skills (as focused plugins) in another reviewer's scope? They need an MIT attribution line for Affaan Mustafa where ECC text survives; only `deploy/kubernetes` records it today.
