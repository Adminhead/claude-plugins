Findings:

- **Every failure is "no skill fired".** The model answers a small, self-contained fix from memory. The cases that pass are multi-step workflows (migrations, audits, setup, release, device work) and upstream skills.
- **Prompt shape alone did not fix it.** First prompts were bare questions. Version 2 named repo files and asked for a fix: the model searched for the files, found none and bailed without a skill. Version 3 (file name plus inline code plus the symptom string, as in the per-plugin trigger cases) changed nothing: 0 of 3 for 16 of the 18 cases that were rerun.
- **Reordering descriptions to lead with the symptoms did not fix it either.** A trial rewrite of the `kotlin`, `kotlin-testing`, `android`, `android-testing`, `jetpack-compose` and `android-build` descriptions to open with "Use when ..." plus the exact error strings left 11 of the 12 rerun cases at 0 of 3 and one at 1 of 3. It was reverted, so no description changed in this run.
- **Per-plugin versus paired.** The same symptoms fire the skill when the plugin loads alone. Only the paired load, with 75 skills, suppresses them. Candidates not yet tested: the skill-listing character budget truncating descriptions, and competing generic skills.
