### Deleted cases

The first full run passed 18 of 36. The other 18 never fired their skill (0 of 3 in a final attempt each; `log-not-mocked` and `webmvctest-kotlin` had reached 1 of 3 in earlier attempts): `agp-minor-bump`, `anr-sharedprefs-commit`, `compose-launched-effect`, `compose-test-sleeps`, `config-cache-task-project`, `generic-test-strategy`, `java-to-kotlin`, `kotlin-testing-uncompleted`, `log-not-mocked`, `manifest-merger`, `no-compose-hierarchies`, `release-gson-classnotfound`, `reusable-card-api`, `sealed-when-exhaustive`, `sharedflow-events-lost`, `statein-rotation-reload`, `viewmodel-main-dispatcher`, `webmvctest-kotlin`.

Attempts, in order, none of which moved a case:
1. Bare questions with no files.
2. Prompts naming repo files that did not exist: the model searched, found nothing and answered without a skill.
3. A file name plus inline code plus the symptom string.
4. A trial rewrite of six leaf descriptions to open with "Use when ..." and the exact error strings.
5. Edit tasks: a scaffold script creates the named files, the prompt says "fix it in the file", and Write and Edit are granted (`--scaffold --allow-tools Write Edit`, no Bash). The model edits the file directly (checked in a trace of `sealed-when-exhaustive`: Glob, Read, Edit, Edit, no Skill call).

Findings:
- **The cause is the model's choice, not the listing.** These are small fixes the model does from memory. `sealed-when-exhaustive` fires 0 of 3 with `kotlin` alone, so the earlier claim that these symptoms fire when a plugin loads alone was wrong for this form of prompt. The per-plugin `trigger-kotlin-1` passes (2 of 3 in the last check) because its prompt carries code plus the exact error text.
- **Separately, the listing budget overflows.** With 75 skills and the default 1% budget, Claude Code cuts descriptions of 13 later-listed skills to name-only (gradle, java, kotlin, kotlin-testing, jetpack-compose, play-publishing, unit-testing, spring-boot-testing, ...). `SLASH_COMMAND_TOOL_CHAR_BUDGET=100000` removes the cut but did not change pass rates. The suite does not set it, because case env keys must match `EVAL_*`.
- **Coverage left.** The deleted cases were the only paired checks for `kotlin`, `kotlin-testing`, `jetpack-compose`, `android-testing`, `unit-testing` and `spring-boot-testing` boundaries. Those leaves keep their per-plugin trigger and hard-negative cases.

### Description changes

All nine leaf descriptions were shortened to 362 to 512 characters (was 570 to 665 for most), with what the skill does and the strongest triggers first, to fit the skill listing budget. Lengths: kotlin 512, kotlin-testing 404, android 451, jetpack-compose 436, android-build 489, android-testing 425, android-device 362, android-performance 408, play-publishing 425. Versions stay 0.1.0 (unreleased). Per-plugin trigger and hard-negative cases were rerun at 1 run each and all passed, except `trigger-kotlin-1`, which passed 2 of 3 on two checks (the symptom string was restored in the description). `recommend-plugins` went to 0.2.1 to suggest `skillListingBudgetFraction` 0.02 to 0.03 with `android-meta`.

Setting verified on code.claude.com (skills and settings pages): `skillListingBudgetFraction`, any settings file, default 1% of context, example `0.02` = 2%. Also `skillListingMaxDescChars` (default cap 1,536 characters per description). `examples/claude-settings/settings.global.json` already sets 0.03, and `scripts/install.mjs` merges it.
