# Eval run, 2026-10-23: paperthin ports

These are the trigger evals for the five model-invoked plugins ported from LilMGenius/paperthin (`docs/plans/paperthin-ports.md`, S6).

Each suite ran with `claude plugin eval plugins/<p> --trust-plugin -j 3`, once per case. The default with/without ablation applied, so every case also ran in a no-plugin baseline arm. The model was set in each case's frontmatter (`claude-sonnet-5-5`).

| ssot-consolidate | 2 positive, 2 hard negative | 4/4 | |

| catchup | 2 positive, 2 hard negative | 4/4 | |

Every positive fired with the plugin and scored 0 in the baseline arm (Δ +1.00). Every hard negative stayed quiet in both arms. The hard negatives were aimed at doubt-review, docs-audit, handoff, necromancy, the-fool, debloat and code dedupe.

There was one run per case, so this rules out gross mis-routing but says nothing about variance. Re-run with `--runs 3` if a description changes.

The first catchup-next grader was an llm rubric. The judge failed a reply that did contain a Next move, so it was replaced with a regex on the label.

Coexistence: a case can list several plugins in its `plugins:` frontmatter, but each entry must resolve under the directory the run targets (the enclosing plugin when the target is inside one, else the directory passed to `claude plugin eval`). A case inside `plugins/<p>/evals/` therefore cannot load a sibling plugin: it fails to load with "outside the containment root". The two existing forgejo-ship cases that list sibling plugins hit the same error. A suite that sits above `plugins/` works: four cases (leakage-audit vs the-fool, ssot-consolidate vs docs-audit, each with a positive for one side and a negative for the other) all scored 1.00 with both plugins loaded together, from a scratch suite with copies of the plugins. They are not committed because no allowed in-repo location fits the layout.
