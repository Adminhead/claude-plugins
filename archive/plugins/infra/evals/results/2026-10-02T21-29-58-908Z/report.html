## What's wrong

**Blockers (these leak secrets into a public image):**
1. **`COPY . .` with no `.dockerignore`.** `.env` and `secrets/signing.key` go into the image layer. Anyone who pulls the image can read them.
2. **The `.npmrc` write.** The token is written to `/app/.npmrc` in the same layer as the install, so it stays in the final image.
3. **`ARG NPM_TOKEN`.** Build args are recorded in `docker history` and the image metadata. Compose passes the token this way too.
4. **`.gitignore` only lists `node_modules` and `dist`.** `.env`, `secrets/` and `.npmrc` are not ignored, so they may be committed. I couldn't check git history from here.

**Should fix:**
- `node:latest` isn't reproducible and is a large image. Pin a version, and use slim or alpine.
- The container runs as root.
- `npm install` should be `npm ci`. The final image also ships dev dependencies and source, so a multi-stage build is better.
- The build is probably broken. `package.json` has `tsc` as the build script but no `typescript` dependency, and there's no `tsconfig.json`. `dist/server.js` therefore won't be produced as written.
- `compose.yaml` hardcodes DB credentials. The `POSTGRES_PASSWORD` and `DATABASE_URL` values are placeholders now, but this is the pattern that gets real values pasted in.
- There's no healthcheck, and no `restart` or `depends_on`.

**Do this before publishing:** if `.env` or `signing.key` were ever committed or built into an image that was pushed, treat them as compromised. Rotate the signing key and the NPM token. Also rotate any other credentials in `.env`, and purge them from git history.
