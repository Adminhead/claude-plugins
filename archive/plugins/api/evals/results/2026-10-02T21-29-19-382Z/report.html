Neither side is safe on its own, and they fail in different ways. I only read the code and didn't run or edit anything, so the fixes below are untested.

## What's wrong

**Client (`app/api_client.js`)**
1. **The key changes on every attempt.** `Idempotency-Key: charge-${Date.now()}` is built inside the retry loop, so each retry carries a new key and the server sees a new request. This is the main cause of your duplicates. A timeout where the first request actually succeeded is the usual trigger. Even with a stable key, `Date.now()` can collide across devices or taps.
2. **Retry policy is unbounded and indiscriminate.** It retries every non-2xx response, including 400, 401 and 422, which can never succeed. It also retries 10 times at a fixed 1s with no jitter, so a fleet re-synchronizes after an outage. There is no overall deadline or per-attempt timeout, and the final error discards the cause.

**Server (`handler.py`, `schema.sql`)**
3. **Check-then-insert race.** Two concurrent retries both run `SELECT`, both see nothing, and both call `processor.charge`. `idempotency_keys` has no unique constraint, so even the later `INSERT` can't stop the duplicate. This is the race the eval is named for.
4. **The key is recorded only after the charge.** If the process dies after `processor.charge` but before `commit`, the card is charged and nothing is stored. The retry charges again. There is also no in-flight state.
5. **The key is global, not per account.** One account's key can replay another account's response.
6. **No payload fingerprint.** The same key with a different amount silently replays the old response.
7. **The replay is lossy and hardcoded.** It always returns 201 and doesn't store the status.
8. **The processor call carries no idempotency key.** Even a correct server can't be crash-safe without one.
9. **The key is optional.** A missing header silently disables all protection.

**`handler.py`**
```python
"""POST /v1/charges, called by integrators and by our own mobile app."""
import hashlib
import json
import time

import processor  # wrapper around the card processor's HTTP API

# Must exceed the processor call's timeout, or a slow request gets taken over.
LOCK_TIMEOUT_S = 60


def _fingerprint(body):
    canonical = json.dumps(body, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(canonical.encode()).hexdigest()


def _error(status, code, message):
    return status, {"error": {"code": code, "message": message}}


def create_charge(db, account_id, headers, body):
    key = headers.get("Idempotency-Key")
    if not key or len(key) > 255:
        return _error(400, "idempotency_key_required",
                      "Idempotency-Key header is required (max 255 chars).")

    fingerprint = _fingerprint(body)
    now = time.time()

    # Atomic claim: the unique constraint picks exactly one winner. Committed
    # before the foreign call so concurrent retries see the in-flight row.
    cur = db.execute(
        "INSERT INTO idempotency_keys"
        " (account_id, idempotency_key, request_fingerprint, locked_at)"
        " VALUES (?, ?, ?, ?)"
        " ON CONFLICT (account_id, idempotency_key) DO NOTHING",
        (account_id, key, fingerprint, now),
    )
    db.commit()

    if cur.rowcount == 1:
        row_id = db.execute(
            "SELECT id FROM idempotency_keys"
            " WHERE account_id = ? AND idempotency_key = ?",
            (account_id, key),
        ).fetchone()[0]
        generation = 0
    else:
        row_id, stored_fp, status, response, locked_at, generation = db.execute(
            "SELECT id, request_fingerprint, response_status, response_body,"
            " locked_at, lock_generation FROM idempotency_keys"
            " WHERE account_id = ? AND idempotency_key = ?",
            (account_id, key),
        ).fetchone()

        if stored_fp != fingerprint:
            return _error(422, "idempotency_key_reused",
                          "This key was used with a different request. "
                          "Use a new key or resend the original payload.")
        if status is not None:
            return status, json.loads(response)  # verbatim replay, no re-execution

        in_flight = _error(409, "idempotency_request_in_progress",
                           "Original request still running; retry with the same key.")
        if locked_at is not None and now - locked_at < LOCK_TIMEOUT_S:
            return in_flight

        # Original executor crashed or stalled: take over atomically and fence it.
        taken = db.execute(
            "UPDATE idempotency_keys"
            " SET locked_at = ?, lock_generation = lock_generation + 1"
            " WHERE id = ? AND response_status IS NULL"
            " AND (locked_at IS NULL OR locked_at < ?)",
            (now, row_id, now - LOCK_TIMEOUT_S),
        )
        db.commit()
        if taken.rowcount == 0:
            return in_flight
        generation += 1

    # Foreign call. The derived key makes a re-run after a crash return the
    # original charge instead of creating a second one.
    ref = processor.charge(
        account_id=account_id,
        amount_cents=body["amount_cents"],
        currency=body["currency"],
        idempotency_key=f"{account_id}:{key}:charge",
    )

    response = {"processor_ref": ref, "amount_cents": body["amount_cents"]}

    # Local write and final response commit together, fenced by generation.
    done = db.execute(
        "UPDATE idempotency_keys"
        " SET response_status = 201, response_body = ?, locked_at = NULL"
        " WHERE id = ? AND lock_generation = ? AND response_status IS NULL",
        (json.dumps(response), row_id, generation),
    )
    if done.rowcount == 0:  # lost the lock to a takeover; commit nothing
        db.rollback()
        return _error(409, "idempotency_request_in_progress",
                      "Request was taken over; retry with the same key.")
    db.execute(
        "INSERT INTO charges (account_id, amount_cents, currency, processor_ref)"
        " VALUES (?, ?, ?, ?)",
        (account_id, body["amount_cents"], body["currency"], ref),
    )
    db.commit()
    return 201, response
```

**`app/api_client.js`**
```js
// Mobile app client for POST /v1/charges.
const BASE = "https://api.example.com";
const MAX_ATTEMPTS = 5;
const BASE_MS = 500;
const CAP_MS = 8000;
const DEADLINE_MS = 30000;
const ATTEMPT_TIMEOUT_MS = 8000;
const RETRYABLE_STATUS = new Set([408, 429, 502, 503, 504]);

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const fullJitter = (attempt) =>
  Math.random() * Math.min(CAP_MS, BASE_MS * 2 ** attempt);

// Mint the key once per user intent (e.g. when the Pay button is tapped) and
// persist it with the pending charge, so a restart retries with the same key.
export const newChargeKey = () => `charge-${crypto.randomUUID()}`;

export async function createCharge(token, charge, idempotencyKey) {
  const deadline = Date.now() + DEADLINE_MS;
  let lastError;

  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    const remaining = deadline - Date.now();
    if (remaining <= 0) break;

    let wait = fullJitter(attempt);
    try {
      const res = await fetch(`${BASE}/v1/charges`, {
        method: "POST",
        headers: {
          Authorization: `Bearer ${token}`,
          "Content-Type": "application/json",
          "Idempotency-Key": idempotencyKey, // identical on every attempt
        },
        body: JSON.stringify(charge),
        signal: AbortSignal.timeout(Math.min(ATTEMPT_TIMEOUT_MS, remaining)),
      });
      if (res.ok) return await res.json();

      const err = await res.json().catch(() => ({}));
      const inFlight = err?.error?.code === "idempotency_request_in_progress";
      if (!RETRYABLE_STATUS.has(res.status) && !inFlight) {
        // 400/401/402/422 etc. cannot succeed on retry (includes key reuse).
        throw Object.assign(new Error(`charge rejected: ${res.status}`), {
          fatal: true, status: res.status, body: err,
        });
      }
      const retryAfter = Number(res.headers.get("Retry-After"));
      if (retryAfter > 0) wait = Math.max(wait, retryAfter * 1000);
      lastError = new Error(`HTTP ${res.status}`);
    } catch (e) {
      if (e.fatal) throw e;
      lastError = e; // timeout or network error: safe to retry because the key is stable
    }
    console.warn(`createCharge attempt ${attempt + 1} failed: ${lastError.message}; waiting ${Math.round(wait)}ms`);
    await sleep(Math.min(wait, Math.max(0, deadline - Date.now())));
  }
  throw new Error(`charge failed after retries: ${lastError?.message}`);
}
```

## Notes and decisions to confirm
- **Existing integrators:** requiring the header returns 400 to any who omit it today. Roll it out with a deprecation notice, or keep it optional and accept that those callers stay unprotected.
- **Transient failures:** I don't store processor errors. They leave the key in flight, so the retry re-attempts after the lock expires, which is safe because the processor dedupes on the derived key. If you'd rather replay declines verbatim, store a 402 on a definitive decline.
- **Retention:** nothing deletes `idempotency_keys` rows yet. Add a reaper (about 72h) and a replay window of at least your longest retry chain, about 24h by default.
- **Database:** the code uses SQLite syntax. On Postgres, `INSERT ... ON CONFLICT` works as written, and `rowcount` behaves the same.
- **Verification:** the next step is a concurrency test, with N parallel identical requests producing exactly one charge. Add a crash test that kills the process after `processor.charge` and then retries.

## What's wrong

Either side alone would still produce duplicates, and the two bugs compound each other.

### Client (`app/api_client.js`)

1. **The key changes on every retry.** `` `charge-${Date.now()}` `` is evaluated inside the loop, so each attempt sends a new key. The server never sees the same key twice, so its dedup never runs. This is the main cause of the duplicate charges you're seeing.
2. **The key is weak.** Two devices, or two taps in the same millisecond, can collide, which would wrongly merge two different charges. The key should be a UUID. It should also be generated once per logical charge and ideally persisted, so it survives an app restart mid-retry.
3. **Retry policy.**
   - It retries every non-2xx response, including 4xx errors that can never succeed.
   - There is no fetch timeout, so a hung request stalls the loop.
   - The delay is a fixed 1s with no backoff or jitter.

### Server (`schema.sql`, `handler.py`)

1. **Check-then-act race.** The handler runs `SELECT`, then calls the processor, then `INSERT`s the key. When the app times out and retries while the first request is still in flight, both requests miss the lookup and both call `processor.charge`. This is the "idempotency race" in the fixture's name.
2. **No uniqueness on the key.** `idempotency_keys.key` has no `PRIMARY KEY` or `UNIQUE` constraint, so the database can't stop duplicate rows. The key also isn't scoped to the account, so two accounts that send the same key would collide.
3. **The processor call isn't covered by the key.** If the process crashes after `processor.charge` but before `commit`, the card is charged and nothing is recorded. The retry then charges again. The key must also be passed to the processor.
4. **No request fingerprint.** Reusing a key with a different body silently returns the old response.

**`schema.sql`**

  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id    TEXT NOT NULL,
  amount_cents  INTEGER NOT NULL,
  currency      TEXT NOT NULL,
  processor_ref TEXT NOT NULL
);

CREATE TABLE idempotency_keys (
  account_id   TEXT NOT NULL,
  key          TEXT NOT NULL,
  request_hash TEXT NOT NULL,
  status       TEXT NOT NULL DEFAULT 'in_progress',  -- in_progress | complete
  response     TEXT,
  created_at   TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (account_id, key)
);

**`handler.py`**
```python
"""POST /v1/charges, called by integrators and by our own mobile app."""
import hashlib
import json

import processor  # wrapper around the card processor's HTTP API


def create_charge(db, account_id, headers, body):
    key = headers.get("Idempotency-Key")
    if not key:
        return 400, {"error": "Idempotency-Key header is required"}

    request_hash = hashlib.sha256(
        json.dumps(body, sort_keys=True).encode()
    ).hexdigest()

    # Atomically claim the key. The PRIMARY KEY makes exactly one concurrent
    # request win; everyone else sees rowcount == 0.
    claim = db.execute(
        "INSERT OR IGNORE INTO idempotency_keys (account_id, key, request_hash)"
        " VALUES (?, ?, ?)",
        (account_id, key, request_hash),
    )
    db.commit()

    if claim.rowcount == 0:
        status, stored_hash, response = db.execute(
            "SELECT status, request_hash, response FROM idempotency_keys"
            " WHERE account_id = ? AND key = ?",
            (account_id, key),
        ).fetchone()
        if stored_hash != request_hash:
            return 422, {"error": "Idempotency-Key reused with a different request"}
        if status == "complete":
            return 201, json.loads(response)
        return 409, {"error": "original request still in progress, retry shortly"}

    try:
        # The processor dedups on the same key, so a crash/retry after this
        # call can't charge the card twice.
        ref = processor.charge(
            account_id=account_id,
            amount_cents=body["amount_cents"],
            currency=body["currency"],
            idempotency_key=f"{account_id}:{key}",
        )
    except Exception:
        db.execute(
            "DELETE FROM idempotency_keys WHERE account_id = ? AND key = ?",
            (account_id, key),
        )
        db.commit()
        raise

    response = {"processor_ref": ref, "amount_cents": body["amount_cents"]}
    # Record the charge and complete the key in a single transaction.
    db.execute(
        "INSERT INTO charges (account_id, amount_cents, currency, processor_ref)"
        " VALUES (?, ?, ?, ?)",
        (account_id, body["amount_cents"], body["currency"], ref),
    )
    db.execute(
        "UPDATE idempotency_keys SET status = 'complete', response = ?"
        " WHERE account_id = ? AND key = ?",
        (json.dumps(response), account_id, key),
    )
    db.commit()
    return 201, response
```

`processor.charge` needs to accept `idempotency_key` and forward it as the processor's own idempotency header. This assumes your card processor supports that, as Stripe and Adyen do. If it doesn't, the crash window in point 3 can't be fully closed. You'd have to reconcile `in_progress` rows against the processor.

If a process dies mid-request, the key stays `in_progress` and clients get 409 indefinitely. You'll want a stale-claim takeover, for example reclaiming rows older than N minutes. That is safe only because the processor dedups on the key.

**`app/api_client.js`**
```js
// Mobile app client for POST /v1/charges.
const BASE = "https://api.example.com";
const MAX_ATTEMPTS = 6;
const TIMEOUT_MS = 15000;

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// Retry network failures, timeouts, 408/409/429 and 5xx. Other 4xx can't succeed.
const isRetryable = (status) =>
  status === 408 || status === 409 || status === 429 || status >= 500;

// `idempotencyKey` is generated ONCE per user intent (when the user taps "Pay")
// and persisted by the caller, so it survives retries and app restarts.
export function newIdempotencyKey() {
  return crypto.randomUUID();
}

export async function createCharge(token, charge, idempotencyKey) {
  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    try {
      const res = await fetch(`${BASE}/v1/charges`, {
        method: "POST",
        headers: {
          Authorization: `Bearer ${token}`,
          "Content-Type": "application/json",
          "Idempotency-Key": idempotencyKey, // same key on every attempt
        },
        body: JSON.stringify(charge),
        signal: AbortSignal.timeout(TIMEOUT_MS),
      });
      if (res.ok) return await res.json();
      if (!isRetryable(res.status)) {
        throw new Error(`charge rejected: ${res.status}`);
      }
    } catch (e) {
      if (e.message?.startsWith("charge rejected")) throw e;
      // network error or timeout: fall through to retry with the same key
    }
    // exponential backoff with jitter, capped at 30s
    await sleep(Math.min(30000, 1000 * 2 ** attempt) * (0.5 + Math.random() / 2));
  }
  throw new Error("charge failed");
}
```

Callers should do `const key = newIdempotencyKey()` once when the user initiates payment, store it with the pending order, and pass it to every call to `createCharge`.
