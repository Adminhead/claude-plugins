**Before merging:**

1. **Rename the title** with a type prefix, for example `feat: add user dashboard`. Use `feat(dashboard): add user dashboard` if you use scopes. Lowercase after the colon is the usual style.
2. **Use the right type.** `feat` gives a minor bump, `fix` gives a patch bump, and `docs`, `chore`, `refactor` and similar usually give no release.
3. **Mark breaking changes** with `!` (for example `feat!:`) or a `BREAKING CHANGE:` footer. Otherwise the major bump won't happen.
4. **Check the squash commit body.** GitHub pre-fills it with the individual commit messages. Footers like `BREAKING CHANGE:` can be hidden there or added by accident, so edit it to match what you want released.
5. **Check for a title lint.** If you have a PR-title check (such as `action-semantic-pull-request`), it should fail on the current title. If you don't have one, consider adding it.

- **Breaking changes:** If the PR breaks an existing API or behavior, use `feat!:` or add a `BREAKING CHANGE:` footer in the squash body. Without one, the release won't be a major bump.
