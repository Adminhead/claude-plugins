# Incremental source generators

## Pipeline rules

- Implement `IIncrementalGenerator` (Roslyn 4.0+). Don't port an `ISourceGenerator` by wrapping it.
- Attribute-driven discovery: `context.SyntaxProvider.ForAttributeWithMetadataName("Ns.MyAttribute", predicate, transform)` (Roslyn 4.3.1+). It is far cheaper than scanning every node. Otherwise use `CreateSyntaxProvider` with a purely syntactic predicate and do semantic work only in the transform.
- Turn syntax and symbols into small immutable, value-equatable models right away: strings, bools, enums and equatable collections (a wrapper around `ImmutableArray<T>` that implements structural equality; plain `ImmutableArray<T>` compares by reference). Never let `SyntaxNode`, `ISymbol`, `SemanticModel`, `Compilation` or `Location` flow into a later stage: their identity changes on every edit and defeats caching. If you need a location for a diagnostic, store file path and spans as values.
- Keep independent inputs in independent providers and combine as late as possible. Don't `Combine` with `CompilationProvider` for convenience; it changes on every keystroke.
- Avoid `Collect()` unless one output truly needs every item. One output per model means editing one declaration regenerates one file.
- Use `WithComparer` when default equality doesn't express semantic equality.
- Transforms and output callbacks are `static`, pure, deterministic and cancellation-aware. Don't read files, clocks, environment variables or mutable statics. Model configuration as providers: `AdditionalTextsProvider`, `AnalyzerConfigOptionsProvider`, `ParseOptionsProvider`.
- Name providers with `WithTrackingName` so tests can assert caching.
- Hint names must be stable and collision-resistant (include namespace, containing types and generic arity). Sort aggregated inputs before emitting.
- Report invalid user input with `SourceProductionContext.ReportDiagnostic`; an exception in a generator becomes a CS8785 warning and drops all its output.
- Call `AddSource` with a `SourceText` that has an explicit encoding (the bundled writer returns UTF-8).

## Compact generator

```csharp
[Generator(LanguageNames.CSharp)]
public sealed class FactoryGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        IncrementalValuesProvider<TypeModel> models = context.SyntaxProvider
            .ForAttributeWithMetadataName(
                "Product.GenerateFactoryAttribute",
                static (node, _) => node is TypeDeclarationSyntax,
                static (ctx, ct) => TypeModel.Create(ctx, ct))
            .WithTrackingName("FactoryModels");

        context.RegisterSourceOutput(models, static (spc, model) =>
        {
            var writer = new SourceWriter();
            writer.WriteLine("// <auto-generated/>");
            if (model.Namespace is { } ns)
                writer.WriteLine($"namespace {ns};").WriteLine();
            writer.WriteLine($"partial class {model.TypeName}").OpenBlock();
            writer.WriteLine($"public static {model.TypeName} Create() => new();");
            writer.CloseBlock();
            spc.AddSource(model.HintName, writer.ToSourceText());
        });
    }
}
```

`TypeModel.Create` normalizes symbol data into values, validates unsupported declarations (non-partial types, nested generics), escapes identifiers with `@` where needed, and derives the hint name. The output callback only renders.

The writer in [../assets/SourceWriter.cs](../assets/SourceWriter.cs) fixes CRLF newlines, applies indentation per line, keeps blocks balanced (`OpenBlock`/`CloseBlock`, `Indent()` scopes), and throws if output is empty or unbalanced. Adapt the namespace, newline and indent style to the repo.

## Tests

Use `GeneratorDriver` directly or `Microsoft.CodeAnalysis.CSharp.SourceGenerators.Testing`. Cover:

- exact hint names and generated text;
- multiple and nested declarations, namespaces (including the global namespace), generics, escaped identifiers, partial types;
- malformed or unsupported inputs and their diagnostic locations;
- additional files, analyzer config options and parse options when consumed;
- output that doesn't depend on input order or OS newlines;
- the generated code compiling without unexpected diagnostics;
- **caching**: a second run with identical inputs, and a run after a narrow edit, with step tracking on.

```csharp
var driver = CSharpGeneratorDriver.Create(
    [new FactoryGenerator().AsSourceGenerator()],
    driverOptions: new GeneratorDriverOptions(IncrementalGeneratorOutputKind.None, trackIncrementalGeneratorSteps: true));

driver = driver.RunGenerators(compilation);
driver = driver.RunGenerators(compilation.Clone()); // identical inputs

GeneratorRunResult result = driver.GetRunResult().Results.Single();
Assert.All(
    result.TrackedSteps["FactoryModels"].SelectMany(s => s.Outputs),
    o => Assert.True(o.Reason is IncrementalStepRunReason.Cached or IncrementalStepRunReason.Unchanged));
```

(`AsSourceGenerator()` here only adapts the incremental generator for the driver API; it is not the deprecated wrapping of an `ISourceGenerator`.) Snapshot tests alone are not enough: identical output can hide a pipeline that recomputes everything.
