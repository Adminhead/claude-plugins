# Reorder

Put a listing back into an order that carries meaning, moving items only. Order is information: kin sit together and the sequence follows one axis a reader can feel. It drifts when items are appended where they were written instead of where they belong.

Adapted from the `reorder` skill in LilMGenius/paperthin (MIT).

## Not for

- Rewording, adding, removing, splitting or merging items.
- The root README plugin catalog. It is generated by `scripts/plugins.py catalog`, so reorder never edits it; change the source order and regenerate.

## Workflow

1. Pin the listing and its items, the ordered set in focus.
2. Name the one principle that makes the order carry the most meaning: lifecycle sequence, dependency, grouping by kind, severity, frequency or alphabetical. If the set already has a latent order, surface and finish it instead of imposing a new one.
3. Cluster kin adjacent, then sequence the clusters by that principle.
4. Move items into the new order in place. Reword nothing; add and remove nothing.
5. If the same set is mirrored elsewhere (a translated copy, a second surface), apply the identical order to each.

## Rules

- Move only. Never reword, add, remove, split or merge an item.
- One principle a reader can name. Do not blend incompatible sorts into one listing.
- Respect a deliberate order. If the current sequence already encodes a real principle, complete and tidy it, and surface the call when it is unclear.
- Keep mirrored copies in lockstep.
- Confirm each item exists before moving it and report a MISS when it does not, never a silent drop.

## Before finishing

1. A reader can name the ordering principle from the result alone.
2. Every item that was there is still there; only positions changed.
3. Kin are adjacent and the sequence follows the one principle end to end.
4. Every mirrored copy carries the identical order.
