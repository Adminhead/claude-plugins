# Work longer than one session

Read this when a goal is too big for one agent session and the way to it isn't clear yet. These are concepts to apply with whatever tracker or notes file the project already uses, not a prescribed tool.

- **Name the destination first.** It might be a spec to hand off, a decision to lock before building, or a change made in place. The destination fixes the scope, and every later item is judged against it.
- **Keep the map as an index.** It lists the decisions made, each with a one-line gist and a link to where the detail lives. A decision lives in exactly one place, so the map never restates it.
- **Make tickets decisions, not build slices.** Each ticket is a question whose answer is a decision, sized to one session. Planning produces decisions, and a ticket that turns into building means you have reached the edge of the map and should hand off.
- **Apply the fog-or-ticket test.** If you can state the question precisely now, make it a ticket, even if it is blocked. If you can't yet phrase it that sharply, leave it as fog in a "not yet specified" section and let it sharpen as earlier decisions land.
- **Work the frontier.** The frontier is the set of tickets that are open, unblocked, and unclaimed. Claim a ticket before starting it so concurrent sessions skip it.
- **Resolve one ticket per session.** Record the answer on the ticket, add a gist to the map, graduate any fog the answer made specific, and move scope-excluded items to an "out of scope" list.
- **Keep decisions with the human.** A ticket that needs a person's judgment is resolved with that person, never by an agent answering for them.
